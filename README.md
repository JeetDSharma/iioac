# IIOAC: Fugitive Source (web)

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.22101723.svg)](https://doi.org/10.5281/zenodo.22101723)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

A browser version of the fugitive-source path of EPA's Indoor and Outdoor Air
Calculator (IIOAC 1.0). No Excel, no macros.

## Run it

    ./serve.sh          # then open http://localhost:8765

It has to be served over HTTP — the dispersion data is fetched as binary, which
`file://` blocks.

## What it does

Name the chemical, pick source parameters, add emission scenarios, hit Calculate. You get outdoor and
indoor air concentrations, wet/dry/total deposition, and acute, chronic, and lifetime
inhalation doses for all seven receptor age groups, at fenceline, outer-boundary, and
community locations. Export CSV for the results.

## How it maps to the workbook

| Workbook | Here |
|---|---|
| `Chemical` | Section 1 of the page |
| `Source Inputs Fugitive` | Sections 2 and 3 of the page |
| `Point+Fugitive Lookup` (loaded from `IIOAC_RunFiles.zip` by VBA) | `data/pf/*.bin` |
| `Fugitive Calculations Prelim` / `Fugitive Calculations` | `engine.js` → `calculate()` |
| `Fugitive Output Prelim` | dose formulas in `calculate()` |
| `lookups` | `data/lookups.json` |

Core relation, unchanged from the workbook:

    concentration = (release_kg_per_day / hours_per_day * 0.2778) * unit_value

`0.2778` converts kg/hr to g/s. `unit_value` is the AERMOD result for the selected
receptor band, release frequency, and emission duration.

## Tests

    cd tests && ./run_all.sh          # 74 assertions, ~2.5 min
    cd tests && ./run_all.sh --fast   # skip the 672-file sweep, ~20 s

Five checks, each catching something the others would not:

    EPA's distribution (347 MB zip)
            │
            │  ① fetch_fixtures.py  ── are these EPA's actual bytes?
            ▼
      iioac_1.0.xlsm ───────────────┬──────────────┐
            │                       │              │
            │ ② fingerprint.py      │ workbook.py  │ ③ convert.py
            │   has the model       │   extracts   │   xlsx → .bin
            │   moved?              │              │
            ▼                       ▼              ▼
      model_fingerprint.json    oracle.py     data/pf/*.bin
                                    │              │
                                    │              ├─ engine.js
                                    │              │      │
                                    └─── ④ compare ───────┘
                                        agree to 5.7e-08

| Check | Catches what nothing else would |
|---|---|
| ① `fetch_fixtures.py` + `fixtures.sha256` | The wrong EPA input. Every check below it would validate happily against a corrupted or silently republished file and report success. |
| ② `fingerprint.py` | A formula or constant moving, including on the 24 sheets no test exercises, so the unported paths still have a tripwire. |
| ③ ④ `test_engine.py` | The engine computing something different from the workbook. |
| ⑤ `test_data.py` | A conversion bug in any of the 672 `.bin` files. Check ④ only exercises 18 of them. |

Check ④ is the one the tool stands on, so its independence matters. `engine.js` reads the
converted `.bin` files; `oracle.py` reads the original AERMOD `.xlsx` through openpyxl.
Different files, different readers, different languages. And `oracle.py` does not restate
the model from the user guide, it asks `workbook.py` to recover it from the workbook's own
formula strings, so the reference is derived from EPA's spreadsheet rather than written
from the same understanding as the code under test. Worst disagreement is 5.7e-08, the
float32 storage limit, which means the gap is the storage format and not the arithmetic.

When EPA publishes a new version these fail on purpose, and each says something different:
① that the bytes changed, ② which formulas moved, ④ whether the numbers still match. See
[ROADMAP.md](ROADMAP.md). Detail on every suite is in `tests/README.md`.

`data/lookups.json` is generated by `tools/build_lookups.py`, not hand-written.

## Data

`data/pf/` holds 672 run files, one per (particle size x urban/rural x met station x
consecutive/cyclical x source subtype) combination, converted from the xlsx files in
`IIOAC_RunFiles.zip`. Each is a flat `Float32Array`: 1460 rows (4 receptor bands x 365
days/year) x 60 columns (15 parameter/statistic groups x 4 emission durations). The
page fetches only the one file matching the current selection, about 350 KB.

Point-source run files are converted too, so wiring up the point path later needs no
new data work.

## Fidelity notes

The Chemical step comes first, as it does in the workbook (`Intro_begin_Click` routes
Chemical -> Source Inputs Fugitive, and `ExportResults` copies the Chemical sheet into
every fugitive export). For fugitive sources the workbook fills `Chemical!F6:F10` with
`RGB(216, 224, 227)`, its grey "not needed" colour, and comments out the required-input
check. No fugitive formula references `Chemical!`, and nothing populates the vapor
saturation cap in `lookups!G63`. So the five properties are collected and exported but
do not change any number; the chemical name and CAS identify the run.

Two further quirks of IIOAC 1.0 are reproduced rather than corrected, so results match
the workbook:

- The fugitive area scaling factor is applied inside the concentration-cap branch, so
  it only reaches blocks that have a cap. Deposition, and everything for vapor, comes
  out unscaled.
- Vapor has no air concentration cap, so vapor air results are neither scaled nor
  capped.

Caps are applied per scenario before scenarios are summed, matching the 2018 change
noted in the workbook's VBA.

## Roadmap

Only the fugitive path is ported, though the AERMOD data for point and area sources is
already converted. [ROADMAP.md](ROADMAP.md) covers what is left, and the plan for
tracking EPA's own updates to IIOAC.
